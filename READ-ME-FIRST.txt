HOW TO UPLOAD (github.com, no command line needed)
--------------------------------------------------
1. Open https://github.com/yameenbux/Taiyabah-Mosque-Website-Rebrand
2. Make sure you are on the branch you want to change (main).
3. "Add file" -> "Upload files".
4. Unzip this first, then drag the CONTENTS of the "taiyabah-pages" folder
   into the browser — not the folder itself, and not this text file. The
   folder structure (access/, newbuild/, portal/, ...) must be kept, because
   that is how GitHub decides which files to replace.
5. Commit.

TWO THINGS THAT WILL BITE IF SKIPPED
------------------------------------
1. UPLOAD index_template.html EVEN THOUGH NOBODY VISITS IT.

   index.html is BUILT from index_template.html. If you upload the built
   index.html but not the template, the repository is left holding an old
   template that does not match the live site. The next time anybody runs
   the build, every change made in the last week is silently undone and the
   site goes backwards with no error anywhere.

   The two always travel together.

2. ONE FILE HAS TO BE DELETED BY HAND.

   A web upload can add and replace files. It cannot delete one.

       portal/supabase2.112.4.js

   is now unused. Delete it on GitHub after uploading: open the file, click
   the bin icon, commit. The site works either way — it is dead weight, not
   a dependency — so this is tidiness, not urgency.

THE KEYS IN THESE FILES
-----------------------
access/config.js and newbuild/config.js contain a Supabase key. It is the
PUBLISHABLE (anon) key and it is meant to be visible in a browser — the real
protection is Row Level Security inside the database. Safe in a public repo.

The service_role / secret key is NOT in any of these files and must never be
put in one. If GitHub ever warns that a push contains a secret, do NOT click
"Allow secret" — cancel, and get the key rotated.
