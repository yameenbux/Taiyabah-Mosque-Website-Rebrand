ALREADY DONE — the app's send button is fixed
  The website migration 040, applied this morning, dropped a database function
  called publish_notice(). The phone app's Cloudflare Worker was still calling
  it, and because that Worker sends the push AFTER it writes the notice, the
  app's "Send notification" button had stopped working AND no notification was
  going out. A janazah announcement would have gone nowhere.

  Migration 050 in this zip has ALREADY BEEN APPLIED to the live database, so
  the app's own trustee screen works again right now. Worth sending one real
  notice from it to confirm, because this failure was invisible from the
  website side.

  Migration 051 has also already been applied.

ONLY YOU CAN DO THIS — two secrets, and then the new screen works
  The new "Send a notification" screen in the Admin Centre needs two settings
  before it can send anything. They go in the Supabase dashboard, NOT in any
  file, and I have not seen and do not want the password.

      Supabase -> Project settings -> Edge Functions -> Secrets -> Add new

      Name:  APP_SENDER_URL
      Value: https://taiyabah-sender.<your account>.workers.dev
             (the same address the app's admin.html talks to)

      Name:  APP_SENDER_PASSWORD
      Value: the password the app's trustee screen asks you for

  Until both are set, the screen says so in plain words and records nothing.
  Once they are set it works immediately — no redeploy.

  IF YOU EVER CHANGE THAT PASSWORD IN CLOUDFLARE, change it here too. It is
  the one thing tying the two systems together.
