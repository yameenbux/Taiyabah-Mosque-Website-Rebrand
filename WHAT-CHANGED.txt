The admissions preview link works again
=======================================

Upload these:

  apply/index.html
  _config.yml
  README.md
  DEPLOY.md

`apply/config.js` is unchanged, so leave the one already in the repo alone.


WHY IT BROKE
------------
_config.yml had `- apply/` in its exclude list. GitHub Pages does not publish an
excluded folder, so apply/ returned 404. It worked before because before that
file existed, everything in the repo was published — which was the problem
_config.yml was added to fix.

The exclusion was deliberate: the form must not be usable before the DPIA. But
it was the wrong tool, and I should have told you it would break the button
rather than leaving you to find a dead link.

Here is what it was actually protecting against, and what it was not. Before
today, the form was complete and looked live. A parent could type their child's
name, date of birth and medical notes, press Send, and have all of it
transmitted to Supabase — which refused it only because the table does not
exist yet. Nothing would have been stored. It would still have been sent,
before the DPIA was written. Being unable to keep data is not the same as not
collecting it. Hiding the folder did nothing about that; it only meant nobody
could find the form to try.


WHAT IT DOES NOW
----------------
apply/ is published again, and the form carries a PREVIEW_ONLY switch. While it
is on:

  * a banner appears at the top, before anyone types, saying it cannot send an
    application and giving the office number;
  * the Send button is disabled and relabelled "Preview only — applications not
    open";
  * the submit handler returns BEFORE the network call, so nothing about a
    child ever leaves the browser.

The third one is the real protection. The first two are so people understand,
and because a disabled button is one line of devtools away from being enabled.

There are now two independent gates, and both have to be opened on purpose:

  1. PREVIEW_ONLY = true in apply/index.html — the browser never sends.
  2. 008_admissions.sql not applied — nowhere for the data to go if it did.


TESTED
------
The test fills in a complete, valid application — parent, address, child, date
of birth, school, class choices, allergies, SEND, both declarations — waits out
the anti-bot timer, re-enables the disabled button from the console, and presses
Send. It then asserts that ZERO requests left the page and that no
"application received" screen appeared.

It also runs the whole submission path against a copy with the flag off, and
proves that still works end to end. That matters: the day the DPIA is signed,
flipping one flag is the entire change, and nobody wants to find out then that
the sending code has rotted in the meantime.


WHEN YOU ARE READY TO OPEN IT, IN THIS ORDER
--------------------------------------------
  1. DPIA signed off, ICO registration in place, the rest of the list in
     DEPLOY.md done.
  2. Apply db/008_admissions.sql.
  3. Set PREVIEW_ONLY = false.
  4. Change the Admissions page button from "have a look at the new form" to a
     real Apply button — search index_template.html for PREVIEW LINK.

Doing 3 before 1 and 2 gives you a form that accepts children's records into a
database nobody has assessed.
